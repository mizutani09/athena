# Solar-convection plots and HTML on XD2000

The scripts live in Git under `tst/nrfld_validation/` and `scripts/`.
Use the same checkout on XD and record its commit in the run manifest.
The plotting entry point is
`tst/nrfld_validation/replot_solar_convection_campaign.py`.
It analyzes existing output; it does not build or run Athena++.

## Python and output requirements

Use a Python environment with `numpy`, `matplotlib`, `h5py`, and `scipy`,
plus `ffmpeg` on `PATH` for MP4 creation. A headless node is supported;
the scripts select the Agg backend. The opacity HDF5 table is needed for
the xz movie's optical-depth-one contour. Pass its actual XD path.

For a segmented campaign, retain `state.json`, each completed case directory,
and each case's `manifest.json`, `run.log`, `athinput.generated`, `.hst`,
restart `.rst`, and paired `prim_xz_slice`/`user_out_var_xz_slice` and
`prim_xy_slice`/`user_out_var_xy_slice` `.athdf` files. The combined report
checks binary, base input, table hashes, grid, CFL, explicit entropy changes,
and predecessor restarts. It reads case names relative to `state.json`;
the generated `summary.json` records relative source paths so the campaign
can be copied to another filesystem prefix. Movies require at least three
ordered frames per plane. If only history was saved, use `--skip-movies`.

## One command for a segmented entropy-feedback campaign

From the repository root, with paths replaced by the XD paths:

```bash
python3 tst/nrfld_validation/replot_solar_convection_campaign.py \
  --feedback-state /path/to/campaign/state.json \
  --opacity-table /path/to/data/opacity_table_rhoT_3p0_6p3.h5 \
  --max-frames 160 --fps 8
```

The default destination is `/path/to/campaign/combined/`. Open
`combined/index.html` for the joined flux checks, plots, and embedded MP4s.
The campaign root `index.html` also links to this analysis. Running the
command again regenerates the analysis.
For history-only output, replace `--opacity-table ...` with `--skip-movies`.

For a campaign without a `state.json`, list consecutive case directories
in time order and set an output directory:

```bash
python3 tst/nrfld_validation/replot_solar_convection_campaign.py \
  --run /path/to/segment_001 --run /path/to/segment_002 \
  --output-dir /path/to/campaign/combined \
  --opacity-table /path/to/data/opacity_table_rhoT_3p0_6p3.h5
```

Add `--allow-s-in-variation` only if the sole intended physics change
between segments is the explicit `problem/s_in` override. If the first
`.hst` lacks its column header, pass `--header-from /path/to/original.hst`.
Do not join different resolutions or source physics into one history.

## Individual-run plots and report

`run_solar_convection.py` already creates the per-run HTML and plots when
the simulation finishes with slices enabled. For output generated by a
different XD job script, the same plotting programs can be run directly:

```bash
python3 scripts/plot_simple_convection.py /path/to/case
python3 scripts/plot_simple_convection_profiles.py /path/to/case
python3 scripts/plot_simple_convection_tau.py /path/to/case \
  --input /path/to/case/athinput.generated \
  --opacity-table /path/to/data/opacity_table_rhoT_3p0_6p3.h5
python3 tst/nrfld_validation/solar_convection_report.py /path/to/case \
  --input /path/to/case/athinput.generated
```

For a full 3D `prim_full` output, also use
`scripts/plot_simple_convection_surface3d.py`,
`scripts/plot_simple_convection_flux3d.py`, and
`scripts/plot_simple_convection_late_profiles3d.py`; each has `--help`
for explicit opacity table and reference profile paths. The per-run report
accepts `--history-header-from` for a restart HST without its own header.
The joined report is the appropriate place to assess long-window
stationarity across restart segments.
